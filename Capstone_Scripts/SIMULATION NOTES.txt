4. HEURISTIC RULES & SOAR ORCHESTRATOR LOGIC
------------------------------------------------------------------------
Ang Wazuh Manager ang nagsisilbing SIEM at HIDS(Host-Based Intrusion Detection System) na sumasalo ng mga logs mula sa endpoints at firewalls.

[Core Behavioral Analytics]
* Rule 5763 (SSH Brute-Force): Nadi-detect ang multiple failed logins na nag-trigger ng correlation rule[cite: 2].
* Rule 100001 (Ransomware): Nadi-detect ang mass file modification (FIM) ng 10+ renames to .locked sa loob ng 60 seconds[cite: 2].
* Rule 100002 (Internal Port Sweeping): Pag-detect ng mga rejected internal connections na parang Nmap scan[cite: 2].
* Rule 100003 (Data Exfiltration): Pag-upload ng malalaking payload (anomaly) palabas ng network[cite: 2].
* Rule 100004 (Living off the Land): Nadi-detect ang pag-spawn ng unauthorized PowerShell processes na may "-ExecutionPolicy Bypass"[cite: 2].
* Rule 100005 (Cryptojacking): Pag-monitor ng sustained 95%+ CPU spikes (via stress-ng) na may active C2 outbound sockets[cite: 2].
* Rule 100006 (Pass-the-Hash): Mabilisang multiple authentications sa magkakaibang internal servers (Lateral Movement)[cite: 2].

[Automated Mitigation (wazuh_orchestrator.py)]
Kapag pumalo ang alinman sa mga rules, hindi na ito nangangailangan ng manual intervention. 
1. Titignan ng Python logic kung ang IP ay kasama sa "Whitelist" (e.g., IT Admin Subnets, authorized network scanners)[cite: 2].
2. Ipapa-ignore ang alert kung ang process ay lehitimo (e.g., TiWorker.exe, chrome.exe)[cite: 2].
3. Kung kumpirmadong malicious, magpapadala ang script ng XML payload sa REST API ng Sophos XG gamit ang wazuh_api_user credentials.
4. I-a-add ng Sophos ang target IP sa Wazuh_Blacklist_Group, at agad mapuputol ang koneksyon dahil sa Rule #9 (SOAR_Auto_Block).
