7. ADVANCED ROUTING CONFIGURATIONS (SIMULATION BYPASS)
------------------------------------------------------------------------
For the external attack simulation to be successful (from Kali Linux to the Remote Worker), the default routing behavior of the nodes needs to be bypassed temporarily. Because the Remote Worker's SSL VPN is on Full Tunnel (tun0), all return traffic is forced to the Sophos XG Hub, resulting in 100% packet loss when pinged by an external attacker.

Here are the Static Routes implemented to fix the asymmetric routing problem in the simulation environment:

1. KALI LINUX (ATTACKER NODE) ROUTING:
   - Problem: The default gateway of VMware (192.168.202.2) does not know the route to the 10.10.10.0/24 subnet.
   - Solution: Added an explicit route towards the VyOS ISP Core.
   - Command Applied: 
     sudo ip route add 10.10.10.0/24 via 192.168.202.135

2. REMOTE WORKER (TARGET NODE) RETURN PATH:
   - Problem: The default gateway was overridden by tun0 (VPN), so reply packets headed for Kali (192.168.202.144) get lost entering the Batangas Hub.
   - Solution: Added a static route to force traffic to pass through the physical interface (ens3) to the VyOS gateway (10.10.10.1).
   - Command Applied:
     sudo ip route add 192.168.202.0/24 via 10.10.10.1

RESULT:
After applying these routing configurations, end-to-end communication was successful. When `./ssh_bruteforce.sh` was executed against 10.10.10.11, it was successfully detected by the Wazuh Agent, triggering the SOAR Orchestrator to block the attacker IP on the Sophos XG.
